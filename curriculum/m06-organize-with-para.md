# M6 · Organize with PARA

Your five folders already exist. This module teaches you when to use each one, with one question doing most of the work: can this be marked complete? A thing you can finish is a Project. A thing you will still be doing next year is an Area. Reference you might want later is a Resource. Finished or dormant work is an Archive. Not sure yet? Inbox.

Files group by what you are trying to accomplish, not what subject they are about. That is the whole trick.

## Agent procedure

Ledger row: M6. Verification ID: `para-folders`.

1. **Explain the five folders with one example each**, in the user's own world where possible: a campaign with a deadline (Project), a client relationship (Area), a prompt library (Resource), last year's finished work (Archive), a thought captured on the run (Inbox).
2. **Teach the decision tree** in four questions: advances a current goal with an end? Projects. Maintains an ongoing responsibility? Areas. Useful someday? Resources. None of those? Archives. Unsure? Inbox, sort later.
3. **Practice on a small safe batch.** Pick about five items from the Inbox (or anywhere the user points). Classify each with the tree, show the proposed destination and a one-line reason for every item, and wait. Gut-level decisions are fine; the system is forgiving.
4. **Move only what is approved.** Every move gets shown before it happens; a broad reorganization is out of scope for this module and would need its own explicit approval anyway. Archive instead of delete, always.
5. **Teach the weekly ritual in two lines.** Five to ten minutes, same time each week: open the Inbox, run each item through the tree, archive finished projects. That habit is what keeps the system from becoming a pile.

### Approval gates

- Every file move: proposed with source, destination, and reason; approved before it happens.
- No deletions in this module, full stop. Archiving is the tool.
