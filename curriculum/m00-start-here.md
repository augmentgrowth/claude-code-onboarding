# M0 · Start here

Welcome. This first module is a ten-minute look around, nothing more. You just watched your vault get built. Now you learn what it is, where things live, and the one habit that makes the rest of setup calm: check the result, not the promise.

Ordinary AI chat keeps you in the middle of every step: ask, copy, paste, move, ask again. What you set up today is different. You describe an outcome, Claude does the file work in front of you, and you approve each real step. Less asking for advice; more handing over work.

## Agent procedure

Ledger row: M0. Verification ID: `vault-scope`. The ledger ships with this row already `in progress`; this module finishes it.

1. **Explain the three Claude surfaces** in five lines or fewer, in plain words: Chat is for conversation. Cowork is guided work across files and services. Code (where we are) works inside a folder the user opened. The lasting idea is *where Claude is working and what it can see*, not the product names.
2. **Restate the two-folders picture.** This folder is the setup kit; the vault is their own notes folder, built outside it. The kit is safe to delete later, and keeping it makes coming back easier.
3. **Tour the vault**, one line per item, reading it through the folder access already granted:
   - The five folders: `00_Inbox` (unsorted capture), `01_Projects` (active work with a finish line), `02_Areas` (ongoing responsibilities), `03_Resources` (reusable reference), `04_Archives` (finished or inactive).
   - The context files: `CLAUDE.md` at the root, `About_Me.md` and `PARA_Guide.md` in `03_Resources`. These tell Claude who the user is and how the vault is organized.
   - The ledger at `03_Resources/ai_harness_setup/Setup_Ledger.md`: the small table that records setup progress so any later session can pick up where this one stopped.
4. **Teach the verify-first habit** in two or three lines: after each change, look at what exists now and check it directly. A confident-sounding message is not evidence; a folder that exists is.
5. **Preview the ladder** in three lines: the modules run in order (M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M10 → M9 → M11), each one is short, and stopping anywhere is fine because the ledger remembers.

### Approval gates

None. M0 changes nothing except the ledger row, and the user already approved ledger writes when the vault was built. Say so if asked.

### Verification — vault-scope

Read the recorded vault path and list its immediate children. Pass: the vault exists at the recorded path and the listing shows the five PARA folders. Never claim the module done without this passing.

### Human documentation

Card for the user to open in their own browser, if they want the background: https://www.augmentgrowth.ai/resources/claude-code-setup/reference/modes-permissions/ — a short page on approval modes. It is reading for them, not material for this session.

### Record

Update the M0 ledger row: status `done`, today's date, the installer version (from this folder's `VERSION` file), `last result` pass with date, card name in `cards surfaced` if shared. Keep the sync-environment note written during the vault build. Then offer M1 or close with the four-part hand-off.
