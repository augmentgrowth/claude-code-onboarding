# Sample project: bake sale rescue

This folder is a practice sandbox. Everything in it is fictional — a made-up community bake sale with messy notes, duplicate files, and a stale to-do list. It exists so you can try your **first win** (the M3 exercise) without pointing Claude at anything real.

The mess is deliberate: inconsistent file names, a `notes_v2_FINAL.txt` that isn't final, an `old/` folder nobody remembers making. In other words, a normal project folder.

## Try this

Open Claude Code at your vault and say:

> "Map the folder 01_Projects/_sample_project_rescue. Tell me what's in it, what looks current vs. outdated, and propose a tidy copy-first scaffold — but don't change anything until I approve."

Claude should read the files, summarize them, and show you a plan (a "manifest" — the list of exactly what would be created and where) before touching anything. Copy-first means the originals stay put; only copies move. That approve-before-change rhythm is the whole lesson.

When you're done practicing, you can archive or delete this folder — it's yours now.
